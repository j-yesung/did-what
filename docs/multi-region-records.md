# 기록의 여러 방문 지역 정책

- 확정일: 2026-09-22
- 상태: 구현 완료 (2026-09-22)

## 배경

기록은 여러 장소를 가질 수 있지만 현재는 지역을 하나만 저장한다. 이 구조에서는 서울 마포구를 기록의 지역으로 고른 뒤 목포의 장소를 추가할 수 있고, 해당 기록이 장소 상세에는 나타나지만 목포 지역 상세에는 나타나지 않는 불일치가 생긴다.

하루나 하나의 여행 기록에서 여러 지역을 방문할 수 있으므로 기록과 지역을 다대다 관계로 다룬다.

## 제품 정책

- 기록은 방문 지역을 최대 10곳까지 가진다.
- 저장하려면 방문 지역이 최소 1곳 필요하다. 방문 장소는 선택 사항이다.
- 같은 지역은 한 기록에 중복으로 저장하지 않는다.
- 지역별 방문 순서나 날짜는 저장하지 않는다. 작성 화면에는 선택한 순서대로 표시하되 순서에 의미를 부여하지 않는다.
- 사용자가 직접 고른 지역과 장소에서 자동으로 포함된 지역을 구분한다.
- 장소를 추가하면 해당 장소의 지역도 방문 지역에 자동으로 포함한다.
- 장소를 제거했을 때 그 지역을 사용자가 직접 고르지 않았고 같은 지역의 다른 장소도 없다면 지역도 자동으로 제거한다.
- 장소가 연결된 지역을 직접 제거하면 영향 범위를 확인한 뒤 해당 지역의 장소도 함께 제거한다.
- 지역 상세나 장소 상세에서 시작한 기록은 해당 값을 미리 선택하되 사용자가 자유롭게 수정하거나 제거할 수 있다.

## 장소 찾기

- 장소 찾기 드로어 상단에 선택한 방문 지역 칩과 `전국` 칩을 표시한다.
- 지역 칩을 고르면 해당 지역의 좌표를 Kakao 장소 검색 기준으로 사용해 주변 결과를 우선한다.
- 지역 칩은 결과를 강제로 제한하지 않는다. 다른 지역의 장소도 선택할 수 있고, 선택하면 그 장소의 지역을 방문 지역에 자동으로 포함한다.
- 선택한 지역이 없거나 `전국` 칩을 고르면 좌표 없이 검색한다.

## 표시 규칙

- 한 기록은 연결된 모든 지역의 지도와 지역 상세에 나타난다.
- 전체 기록 목록에서는 같은 기록을 한 번만 표시한다.
- 공간이 좁은 기록 카드에서는 지역을 두 곳까지 직접 표시하고 나머지는 `외 N곳`으로 줄인다.
  - 두 곳: `마포구 · 목포시`
  - 세 곳 이상: `마포구 · 목포시 외 2곳`
- 기록 상세에서는 모든 방문 지역을 칩으로 표시한다.
- 작성 화면에서는 방문 지역을 위쪽 칩 목록으로 표시하고 각 장소에는 해당 지역명을 표시한다.

## 데이터와 검증 원칙

- `record_regions` 관계를 기록의 방문 지역 기준 데이터로 사용한다.
- 지역 관계에는 지역 코드, 이름, 표시명, 좌표와 사용자의 직접 선택 여부를 저장한다.
- 기존 기록의 단일 지역은 `record_regions`로 이전하고 직접 선택한 지역으로 취급한다.
- 서버는 장소를 검증한 뒤 각 장소의 지역을 직접 구하고, 사용자가 고른 지역과 합쳐 중복 없이 저장한다.
- 모든 장소의 지역이 기록의 방문 지역에 포함된다는 조건을 서버 쓰기 경계에서 보장한다.
- 지도 위치 조회와 지역 상세 조회는 `record_regions`를 기준으로 하며, 전체 기록 개수는 기록 ID를 기준으로 중복 집계하지 않는다.

## 작성 상태 규칙

작성 화면의 상태는 다음 두 입력을 구분해서 관리한다.

- 사용자가 직접 선택한 지역 목록
- 지역 정보가 포함된 방문 장소 목록

화면에 보여주는 방문 지역은 두 목록의 합집합이다. 이 구조를 사용하면 장소 추가·제거에 따라 파생 지역을 계산할 수 있고, 직접 선택한 지역은 장소를 제거해도 유지할 수 있다.
