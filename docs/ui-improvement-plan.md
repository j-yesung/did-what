# UI 개선 계획

기록 탐색과 작성 경험을 다듬기 위한 단기 개선 항목이다. 각 항목은 독립적으로 구현하고 검증하며, `use-funnel`은 도입을 전제로 하지 않고 현재 구조에 필요한지 먼저 판단한다.

## 작업 항목

### 1. 기록 목록에서 메모 제거

- [ ] `RecordCard`에서 메모 미리보기를 제거한다.

- 날짜, 활동 제목, 지역, 날씨는 유지한다.
- 공용 `RecordCard`를 사용하는 메인 기록 목록과 장소·지역 상세의 기록 목록에 동일하게 적용한다.
- 기록 상세 화면의 전체 내용은 유지한다.

완료 조건:

- 모든 기록 목록에서 메모가 노출되지 않는다.
- 카드 이동, 프리페치, 상세 화면 표시는 기존과 동일하게 동작한다.

### 2. 지도/지역 세그먼트 상단 고정

- [ ] `/`와 `/regions`의 공통 `MapSegment`를 스크롤 중에도 상단에 고정한다.

- iOS PWA의 `safe-area-inset-top`을 반영한다.
- 고정된 영역 뒤로 콘텐츠가 비치지 않도록 배경과 여백을 처리한다.
- 하단 탭 전환 애니메이션과 스와이프 뒤로가기 동작은 변경하지 않는다.

완료 조건:

- 지도와 지역 화면에서 긴 콘텐츠를 스크롤해도 세그먼트를 바로 사용할 수 있다.
- 노치가 있는 iOS PWA에서도 상태 표시 영역과 겹치지 않는다.
- 지도/지역 전환 및 기본 스와이프 뒤로가기가 기존과 동일하게 동작한다.

### 3. 지도/지역 세그먼트 다크 모드 개선

- [ ] 다크 모드에서 세그먼트의 배경, 선택 영역, 텍스트 대비를 높인다.

- 공용 `SegmentedControl`의 다른 사용처에 영향을 주지 않도록 `MapSegment` 범위에서 해결한다.
- 컴포넌트의 직접적인 색상 덮어쓰기보다 라이트·다크 모드에 대응하는 시맨틱 토큰을 사용한다.

완료 조건:

- 라이트·다크 모드 모두 선택된 항목과 선택되지 않은 항목을 명확히 구분할 수 있다.
- 기록 작성의 날씨 세그먼트 등 다른 공용 컴포넌트의 색상은 바뀌지 않는다.

### 4. 텍스트와 이미지 드래그 방지

- [ ] 일반 텍스트 선택과 이미지 드래그를 앱 전역에서 방지한다.

- 기존 링크의 iOS 길게 누르기 미리보기 방지 설정을 유지한다.
- `input`, `textarea`, `contenteditable`은 텍스트 선택, 커서 이동, 수정, 붙여넣기가 가능하도록 예외 처리한다.
- Drawer의 기존 선택 관련 스타일이 전역 정책을 덮어쓰지 않는지 확인한다.

완료 조건:

- 일반 화면에서 텍스트나 이미지를 길게 눌러도 선택·드래그되지 않는다.
- 입력 요소에서는 커서 이동과 텍스트 편집이 정상적으로 동작한다.
- 키보드 탐색과 포커스 표시는 영향을 받지 않는다.

### 5. 기록 작성 `use-funnel` 도입 검토

- [ ] 기록 작성 화면이 실제 다단계 흐름을 필요로 하는지 먼저 결정한다.

- 단순히 `RecordForm`의 코드가 한곳에 모여 있다는 이유만으로 라이브러리를 도입하지 않는다.
- 도입을 검토할 때 현재 `LeaveGuard`, dirty 상태, 작성·수정 모드, 브라우저 히스토리, iOS 스와이프 뒤로가기와의 충돌 가능성을 확인한다.
- 도입하지 않는다면 현재 필드 컴포넌트 구조를 유지하고, 제출이나 이탈 방지 책임이 더 커질 때만 별도 훅으로 분리한다.

도입 조건:

- 기록 작성을 여러 전체 화면 단계로 나눈다.
- 단계별 검증과 이전 단계 복귀가 필요하다.
- 이전 단계로 돌아가도 각 단계의 입력값을 유지해야 한다.
- 작성과 수정 화면의 단계 및 뒤로가기 정책이 명확하다.

현재 판단:

- 현행 단일 화면 작성 UI에는 도입하지 않는다.
- 다단계 작성 UX가 제품 요구로 확정되면 Next.js App Router용 `@use-funnel/browser`로 작은 프로토타입을 만든 뒤 도입 여부를 결정한다.

## 권장 실행 순서

1. 기록 카드 메모 제거
2. 지도/지역 세그먼트 상단 고정
3. 지도/지역 세그먼트 다크 모드 개선
4. 전역 드래그·선택 방지와 입력 요소 예외 처리
5. 다단계 기록 작성 UX 필요 여부 결정
6. 필요한 경우에만 `use-funnel` 프로토타입 및 뒤로가기 충돌 검증

## 검증 원칙

- 코드 변경 후 `pnpm exec biome check --write src app`을 실행한다.
- 컴포넌트 경계나 타입을 변경하면 `pnpm exec tsc --noEmit`을 실행한다.
- 모바일 뷰포트에서 라이트·다크 모드, 긴 스크롤, 입력 편집을 확인한다.
- safe area, 길게 누르기, 기본 스와이프 뒤로가기는 최종적으로 iOS PWA 실기기에서 확인한다.
- `use-funnel`을 도입해 클라이언트 경계나 의존성이 바뀌는 경우에만 프로덕션 빌드 검증을 추가한다.
