# 기록 지도 검토 결과 (2026-10-28)

- 범위: `/journey` 화면과 이 화면이 쓰는 공용 부품(집 주소 시트, 기록 상세 시트, 홈 지도 기록 목록, 공용 시트·버튼, 테마 토큰).
- 방법: 흐름·화면·상태·접근성·성능·서버·코드 7개 관점에서 코드를 읽어 찾고, 관점마다 독립 검증 2명이 "코드가 실제로 그렇게 동작하는지"와 "이미 정한 결정과 충돌하지 않고 고칠 가치가 있는지"를 따로 반박했다. 이어서 빠진 영역(기능 사이 상호작용, 극단적인 경우)을 한 번 더 찾아 같은 방식으로 검증했다. 85개 중 둘 다 통과한 71개를 같은 문제끼리 합쳐 정리했다. 실기기 확인이 아니라 코드 기준이다.
- 표시: ✅ 는 반영한 항목이다. **[공용]** 은 고치면 다른 화면에도 영향이 가는 항목이다. 줄 번호는 검토 시점 기준이라 함수·요소 이름도 함께 적었다.

## 운영 전 확인

- 경로 캐싱: 받은 경로를 새로고침 전까지 메모리에 캐싱해 다시 보기와 수정 후 돌아왔을 때 재사용한다. 카카오 데브톡에 "실시간이 아닌 임시 캐싱 등의 방법으로 API 호출 및 이용은 금지"라는 답변(공식 여부·근거 조항 미확인)이 있어, 운영 전에 카카오에 허용 여부를 확인한다. 허용되지 않으면 다시 보기 때도 새로 조회하도록 바꾼다.

## 높음

### ✅ 1. 제주 기록이 지도와 목록에서 통째로 빠진다 [공용: 홈 지도 포함]

- 문제: 카카오가 주는 제주 법정동 코드는 `50`으로 시작하는데(예: `5011000000`), 지역 정의는 제주를 `49`로만 인식한다. 제주 기록은 시·도 코드가 `null`이 되어 기록 지도에 점이 생기지 않고, 지역 목록과 지역별 기록 목록, 홈 지도의 제주 시트에서도 빠진다. 강원(`42`,`51`)·전북(`45`,`52`)은 특별자치도 전환 후 코드를 함께 두었는데 제주만 없다.
- 위치: `src/entities/region/model/region.ts:25`, `getRegionCode`(41-43) → `src/pages/journey/model/record.ts`의 `toJourneyRegions`에서 건너뜀.
- 확인: `getRegionCode("5011000000")`은 `null`, `getRegionCode("4911000000")`은 `KR-49`(직접 실행).
- 제안: `administrativeCodes: ["49", "50"]`로 고치고 `korea-map.test.mjs`에 `getRegionCode("5011000000") === "KR-49"` 단정을 더한다.

### ✅ 2. 라이트 테마에서 dark 범위 밖으로 나가는 요소들이 밝게 그려진다

- 문제: 지도 화면은 `<main>`에만 `dark`를 건다. 그런데 화면 밖으로 포털되는 요소는 앱 테마를 따른다.
  - **뒤로가기 버튼**(가장 심각): 마운트 후 `#page-back-slot`으로 옮겨져, 라이트 테마에서는 검은 지도 위에 25% 흰 유리와 거의 검은 꺾쇠(대비 약 2:1)로 그려진다. 같은 줄의 "…"·"지역 목록"과 색이 정반대이고, 첫 화면(다크)에서 하이드레이션 직후 색이 뒤집힌다. 하단 탭이 없는 화면이라 유일한 나가기 버튼이다.
  - **시트 배경막**: dark는 시트 본체에만 붙어, 시트를 열 때마다 지도 위에 밝은 막이 씌워진다.
  - **기록 상세의 "⋮" 메뉴, 댓글 삭제 확인창**: 어두운 시트 위에 흰 팝오버·다이얼로그가 뜬다.
- 위치: `src/shared/ui/layouts/page-back-button.tsx:39`, `src/shared/ui/bottom-sheet.tsx:78,107`, `src/entities/record/ui/record-action-toolbar.tsx:63`, `comment-row.tsx:51`.
- 제안: journey에 있는 동안 `document.documentElement`에 `dark`를 붙이고(나갈 때 원래대로) 한 번에 해결한다. 테마 색(theme-color)도 함께 맞는다. 개별로 고치려면 `PageBackButton`에 `className`을 받게 하고, 시트 포털·메뉴·댓글 확인창에 `dark`를 내려준다.

## 중간

### ✅ 3. 시트가 닫히는 동안 내용이 엉뚱하게 바뀐다

- 문제: 시트를 열지 여부와 내용이 `sheet` 상태 하나에 묶여 있다. 닫기가 시작되는 순간 `sheet`가 `null`이 되어, 내려가는 동안 목록이 비고 가운데 정렬된 "{지역}의 기억"과 "다시 보고 싶은 지역을 선택해 주세요."가 보인다. 쓸어 닫으면 `region`까지 비어 제목이 "의 기억"만 남는다. **기록을 고를 때마다** 보인다.
- 같은 원인: 상세 시트에서 기록을 삭제하면 `reset()`으로 `record`가 바로 `null`이 되어, 삭제 확인창이 닫힘 애니메이션 없이 사라지고 상세 시트는 빈 채로 내려간다.
- 위치: `journey-map.tsx` `showSheet`(320-325), `open={sheet !== null}`(937), 내용 분기(954, 974-985), `onOpenChange`의 `setRegion(null)`(946), 상세 시트 `onDeleted`(1051-1058).
- 제안: 그릴 내용용 상태를 따로 두고 `null`이 아닐 때만 갱신해, 닫히는 동안 마지막 내용을 유지한다. `setRegion(null)`은 `onOpenChangeComplete(false)`로 옮긴다. 홈 지도의 `onCloseComplete` 처리와 같은 방식이다. 상세 시트에는 "기록 읽기"를 누를 때 기록을 별도 상태에 담아 넘긴다.

### ✅ 4. 지역 점 위에서 시작한 드래그와 핀치가 무시된다

- 문제: 점이 `pointerdown`의 전파를 막아서, 점의 터치 영역(지름 44px)에서 시작한 이동·확대는 지도가 받지 못한다. 핀치 중 한 손가락이 점에 닿으면 확대 대신 한 손가락 이동이 된다. 지역 이름을 보려고 점이 모인 수도권을 확대할 때 자주 걸린다.
- 위치: `journey-map.tsx` 점 `<g>`의 `onPointerDown={(event) => event.stopPropagation()}`(691), 지도 포인터 추적(634-648).
- 제안: 전파 차단을 없애고 지도가 모든 포인터를 추적하게 한다. `setPointerCapture`는 몇 px 이상 움직였을 때만 걸고, 거의 움직이지 않고 뗀 경우만 탭으로 보아 이미 있는 `toMapPoint`·근처 점 계산으로 지역을 고른다.

### ✅ 5. 경로 오류 문구가 원인과 맞지 않는다

- 문제
  - 네트워크가 끊기거나 응답이 JSON이 아니면(세션 만료로 로그인 HTML이 오는 경우 포함) 브라우저 영문 원문("Load failed" 등)이 오류 줄에 그대로 뜬다.
  - 카카오 주소 검색이 잠깐 늦거나 실패해도 "집 주소를 확인하지 못했어요. 설정에서 주소를 확인해 주세요."라고 안내한다. 주소는 저장할 때 검증하므로 이 시점의 실패는 대개 일시 장애다.
  - 집 주소 저장에서도 카카오 타임아웃·네트워크 오류의 영문 원문이 시트에 그대로 나온다.
- 위치: `journey-map.tsx` `fetchRoute`(154-158), `run`의 catch(455-462), `src/pages/journey/api/directions.ts:34,39-41`, `src/features/home-address/api/geocode.ts:9-15`.
- 제안: `fetchRoute`에서 fetch·JSON 실패를 잡아 "경로를 불러오지 못했어요. 연결을 확인하고 다시 시도해 주세요." 같은 고정 문구로 바꾸고, 서버가 준 `error`만 그대로 쓴다(앱의 `get-error-message.ts` 방식). 서버는 주소 검색 장애를 "잠시 후 다시 시도해 주세요"로 안내하고, 주소 자체 문제(결과 0건·2건)만 따로 구분한다. 문구의 "설정에서"는 뺀다.

### ✅ 6. 이어 보기(수정하고 돌아오기)가 어색하다

- 문제
  - 기록 데이터를 다시 받는 동안 세션이 없어서, 전국 지도·점·"지역 목록"이 먼저 보였다가 기록 화면으로 바뀐다. "첫 화면에 한 번에 그리기" 원칙과 어긋난다.
  - 복원은 항상 "다시 보기"로 처리되어(`Boolean([])`도 참), 모든 구간을 다시 그릴 때까지 "…"와 "기록 읽기"가 숨고 눌리지 않는다. 방금 고친 기록을 확인하기 어렵다.
  - 재조회 중에 사용자가 다른 지역이나 기록을 열어도, 재조회가 끝나면 URL의 옛 기록으로 덮어쓴다.
  - 개발 모드(StrictMode)에서 캐시가 신선하면 복원이 "불러오는 중"에 멈춘다(운영 빌드에서는 생기지 않음).
- 위치: `journey-map.tsx` `initialUrl`(304-308), 복원 effect(552-556), `restoreJourney`(539-549), `begin`의 `replaying`(488), 정리 effect(407).
- 제안: URL에 `region`·`record`가 있으면 복원 전에도 점과 "지역 목록"을 그리지 않는다(서버가 searchParams로 기록 제목·장소까지 넘기면 첫 렌더부터 기록 화면을 그릴 수 있다). `begin`에 "다시 보기 여부"를 따로 넘겨 복원에서는 버튼을 숨기지 않는다. `restoreJourney`는 이미 세션이나 시트가 있으면 건너뛴다. 정리 effect에서 `restored`를 되돌린다. 집 구간은 URL 값만으로 미리 요청을 걸어 둘 수 있다.

### ✅ 7. URL 갱신이 Next 라우터를 우회해 히스토리가 하나 더 쌓인다 [공용 패턴]

- 문제: `history.replaceState(window.history.state, …)`로 주소를 바꾸면 Next가 바뀐 주소를 모른다. 이후 재검증 서버 액션(기록 상세의 장소 저장 토글, 기록 삭제)이 끝나면 Next가 옛 주소(`/journey`)로 push해서, 뒤로가기를 한 번 눌러도 화면이 그대로이고 이어 보기 파라미터도 빠진다.
- 위치: `journey-map.tsx` URL 동기화 effect(537). 같은 패턴이 `src/widgets/region-activity-map/ui/region-activity-map.tsx:97`과 달력·필터에도 있다.
- 제안: `window.history.replaceState(null, "", url)`로 바꿔 Next가 내부 상태를 맞추게 하고, 새 주소가 현재와 다를 때만 호출한다.
- 남은 일: 기록 지도만 고쳤다. 홈 지도(`region-activity-map.tsx`)·달력·필터의 같은 패턴은 화면마다 동작 확인이 필요해 그대로 두었다.

### ✅ 8. 경로 카메라가 제목과 하단 패널에 가린다

- 문제: 경로 맞춤이 화면 전체 높이 기준이라, 서울→대전·광주·제주처럼 세로로 긴 경로는 북쪽 끝(집)이 화면 위 17% 지점, 즉 제목·"기록 읽기" 줄 밑에 깔린다. 낮은 화면(iPhone SE)에서는 남쪽 끝이 하단 패널에도 걸린다. 장소 구간의 "이미 보임" 판정도 제목에 가린 경로를 보인다고 본다.
- 위치: `journey-map.tsx` `routeBox`(109-112), `followBox`(122-128), `.recordHeader`(module.css:134).
- 제안: 세로 여백 배수와 기준점을 조정한다(예: 1.8→2.3, 0.45→0.5). 기기마다 정확히 맞추려면 제목 블록 아래와 패널 위를 재서 그 사이에 맞추고, `followBox` 판정에도 같은 값을 쓴다.

### ✅ 9. 포커스가 사라지는 곳이 있다 (스크린리더·키보드)

- 문제: 기록을 고르면 시트를 열었던 점과 "지역 목록"이 사라져 포커스가 돌아갈 곳이 없다. 기록을 고르지 않고 닫아도 SVG 점으로는 포커스가 돌아오지 않는다. "…" 메뉴는 열 때 첫 아이콘으로 포커스를 옮기지만, 닫힐 때는 "…"로 돌려주지 않는다. 열린 동안 "…"가 숨어 펼침 상태도 전달되지 않는다.
- 위치: `journey-map.tsx` `begin`(468-494), 시트 `onOpenChangeComplete`(938-942), `journey-actions.tsx` 닫는 경로(33-38, 81-84).
- 제안: 시트가 다 닫힌 뒤 세션이 있으면 제목(h1, `tabIndex={-1}`)으로, 없으면 시트를 연 점으로 포커스를 옮긴다. 메뉴가 닫힐 때 포커스가 메뉴 안에 있었으면 "…"로 돌려준다(메뉴가 사라지는 "다시 보기"·"전국 지도로"는 제목이나 "지역 목록"으로). 네 아이콘 묶음에 `role="group"`과 이름을 준다.

### ✅ 10. 동작 줄이기 설정에서 장소 강조 링이 사라지지 않는다

- 문제: 그려진 배지를 다시 누르면 생기는 초록 링이, 동작 줄이기에서는 애니메이션 없이 불투명도 0.8로 계속 남는다. 같은 설정에서 현재 지점의 파동도 같은 크기의 정지된 초록 링이 되어, 지나온 장소와 현재 위치가 둘 다 초록 링으로 보인다.
- 위치: `journey-map.module.css` `.focusRing`의 reduce 규칙(346-349), `highlight`는 `begin`·`reset`에서만 지움.
- 제안: 동작 줄이기에서는 크기 변화 없이 불투명도만 1~1.5초에 걸쳐 빠지게 하고, 새 장소를 고를 때 `setHighlight(null)`을 부른다.

### ✅ 11. 폭 440pt 기기에서 지도 양옆에 바탕색 띠가 생긴다

- 문제: `.page`가 최대 폭 430px로 가운데 정렬되어, iPhone Pro Max(440pt)에서는 좌우 5px씩 body 배경이 드러난다. 라이트 테마면 검은 지도 옆에 밝은 세로선이 생긴다.
- 위치: `journey-map.module.css` `.page`(8-13).
- 제안: 시트처럼 700px 이상에서만 폭을 제한한다: `@media (min-width: 700px) { .page { max-width: var(--app-width); } }`.

### ✅ 12. 집에서 오는 첫 선이 대표 지역이 아닌 엉뚱한 구에서 끝난다

- 문제: 한 시·도 안에 시·군·구가 여럿인 기록은 이름 가나다순 첫 지역을 도착점으로 고른다. 그래서 사용자가 직접 고른 대표 지역이 무시된다. 저장한 장소에서 딸려 온 지역은 장소 좌표를 지역 좌표로 쓰므로, 예를 들어 "서울 성동구"를 고르고 강남 식당을 넣으면 집 선이 이름표 없는 강남 식당 자리에서 끝나고, 성수 카페 배지를 누르면 거기서 다시 출발한다. 강릉·속초, 제주시·서귀포시 같은 여행 기록에서 흔하다.
- 위치: `src/pages/journey/model/record.ts`의 `toJourneyRecord`(17-19)와 그 테스트, 서버 조회 `api/records.ts:13`·`api/directions.ts:46`, 클라이언트 캐시 컬럼 `src/entities/record/api/record-columns.ts:7`.
- 제안: 이 시·도 안에 대표 지역(`records.region_code`, 저장 시 첫 지역)이 있으면 그것을, 없으면 `selected_directly`인 지역을, 그래도 없으면 가나다순을 쓴다. 이미 있는 `sortPrimaryRegionFirst`(`record-region.ts:9-13`)를 재사용하고, 서버 조회 두 곳과 클라이언트 캐시 컬럼에 같은 값을 넣어 화면과 서버가 같은 점을 고르게 한다. 테스트 기대값도 바꾼다.

### ✅ 13. 섬 기록이면 지역 점이 첫 화면 밖에 찍힌다

- 문제: 시·도 점은 그 시·도의 최근 기록 도착점에 찍는다. 경북의 최근 기록이 울릉도라면 경북 점이 첫 화면 오른쪽 밖에 있어 바로 누를 수 없고, 지역 목록이나 축소로만 찾을 수 있다. 서해 섬(백령도 등)도 같은 경우가 생길 수 있다.
- 위치: `journey-map.tsx`의 `national`(75-82), `toJourneyRegions`(`record.ts:44-52`).
- 결정과의 관계: 첫 화면을 홈 지도처럼 본토 기준으로 맞추고 섬은 축소하면 보이게 한 결정은 그대로 둔다(틀을 넓히자는 제안은 채택하지 않음).
- 제안: 점 위치를 화면 안에 오는 값으로 정한다. 예를 들어 점이 첫 화면 틀 밖이면 시·도 대표 위치(본토 쪽 중심)에 찍는다. 점 위치가 최근 기록을 따라 옮겨 다니는 지금 방식(기록을 추가하면 점이 이동함)도 이때 함께 정리하면 좋다.

### 코드

- **시트 높이 측정 로직이 두 곳에 복제돼 있다** [공용 훅 후보]: journey와 집 주소 시트에 `+29` 측정, ResizeObserver, 250ms 펼침 대기가 거의 그대로 있다. `useCompactSnapPoint` 훅과 손잡이 높이 상수를 `bottom-sheet` 쪽에 둔다.

- **경로 응답 타입이 서버와 클라이언트에 따로 있다**: 서버 필드 이름이 바뀌어도 타입 오류 없이 화면이 깨진다(`straight` 안내 등). `JourneyRoute`·`JourneyRegion`·`JourneyStatus`를 model에서 내보내 같이 쓰고, 이름이 겹치는 `JourneyPlace` 두 개를 정리한다.
- **아무도 읽지 않는 `title`·`date`**: 이 값 때문에 서버 조회가 컬럼을 더 가져오고 빈 `record_places`를 지어 넣는다. 지우고 `toJourneyRegions`는 `record_regions`만 받게 한다.
- **서버 코드가 기존 규칙과 공용 코드를 따르지 않는다** [공용: 설정]: 길찾기 핸들러 구현만 `src/app/route-handlers`가 아니라 pages에 있고, `isUuid`·`getRegion` 대신 정규식을 새로 썼으며, 현재 구성원의 집 주소 조회가 세 곳(설정·journey 페이지·길찾기)에 복사돼 있다.
- **지도 색이 CSS 모듈에 직접 정의돼 있다**: 컨벤션은 원시 색 값을 `globals.css` 토큰 밖에서 쓰지 말라고 한다. 다섯 색을 토큰 구역으로 옮기고 홈 지도의 `--map-*`와 겹치지 않는 이름(`--journey-*`)을 쓴다. 카카오 주소 검색 iframe 색은 예외로 둔다.
- **쓰이지 않는 코드**: 클라이언트가 읽지 않는 오류 `code`, 효과 없는 `font-family: inherit`. 마우스 휠 확대와 grab 커서는 모바일 전용 기준으로는 불필요하지만, 데스크톱에서 확인할 때 쓰고 있다면 남겨 둔다.
- **같이 바뀌어야 할 숫자가 흩어져 있다**: 선 그리기 900ms가 JS 두 곳과 CSS 한 곳에 따로 있어 하나만 바꾸면 어긋난다. `SKETCH_MS` 하나로 묶어 CSS에는 변수로 넘긴다. 메뉴의 `COLLAPSED_WIDTH`(52)도 `--toolbar-height`와 같은 값이라는 게 드러나게 한다.

## 검증에서 제외한 항목

다음은 찾았지만 검증에서 빠졌다. 이미 의도한 동작이거나, 실제 효과가 확인되지 않았거나, 고칠 가치에 비해 과하다는 판단이다.

- 기록 읽기 → 수정 → 저장하면 기록 상세에 도착함: 지도 시트에서 시작한 수정에 일부러 둔 공용 동작(`use-leave-guard.ts`)이고 홈 지도와 같다.
- 목록에서 지금 보던 기록을 다시 고르면 장소가 초기화됨: 배지를 한 방향으로만 고르는 결정에서 유일한 초기화 방법이다.
- 전국 화면으로 되돌아가는 버튼이 없음: 핀치 아웃으로 충분하다.
- 카메라 프레임마다 화면 전체가 다시 렌더됨, 시트가 덮어도 파동 애니메이션이 돎, pointerdown 미리 받기 낭비: 실제 비용이 측정되지 않았고 결정한 동작이다.
- `revalidatePath` 뒤 `router.refresh()` 중복: 영향이 작아 제외했다(쓰이지 않는 코드 항목과는 별개).
- 지역 점과 기록 목록이 다른 조회를 씀, 테스트 보강, 이름 재사용·빈 줄 정리: 효과가 불분명하거나 과한 변경이다.
- 선을 그리는 중에 사용자가 기록 읽기·목록 시트를 열면 그리기가 시트 뒤에서 끝남: 직접 연 시트이고 닫으면 최종 상태가 남으며 다시 보기로 볼 수 있다.
- 지도 경계 JSON(약 421KB)이 첫 진입 청크와 SSR HTML에 실림: 홈에서 들어오면 캐시를 쓰고 체감 이득에 비해 구조가 복잡해진다.
- 카카오 결과 코드가 0이 아니면 모두 "도로 없음"으로 봄: 일시 장애(타임아웃·429·5xx)는 HTTP 실패라 오류로 가므로 과장이었고, 5m 이내 문제는 별도 항목으로 다룬다.
