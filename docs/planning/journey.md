# 기록 지도(journey)

- 경로: `/journey`. 집에서 기록의 지역, 그리고 사용자가 고른 장소 순서대로 자동차 추천 경로를 그려 추억을 따라간다.
- 화면 동작은 코드(`src/pages/journey`)가 기준이다. 이 문서에는 코드만 봐서는 알 수 없는 결정과 남은 일을 둔다.

## 결정과 제약

- 선과 거리·시간은 조회 시점의 자동차 추천 경로이고, 장소를 잇는 순서는 사용자가 배지를 누른 순서다. 실제 이동 경로·소요 시간·방문 순서로 표시하지 않으며 선택 순서를 저장하지 않는다.
- 집 주소(`member_home_addresses`)는 계정과 현재 구성원 조합마다 하나다. 같은 계정의 구성원은 계정 권한을 공유하므로 서로의 주소를 완전히 분리하는 보안 경계는 아니다. 주소 문자열만 저장하고 좌표는 저장하지 않으며, 주소 확인과 집 출발 구간 조회 때마다 카카오 주소 검색으로 변환한다.
- 길찾기 서버는 기록 소유자와 지역·장소 연결을 확인한 뒤에만 조회한다. 브라우저가 보낸 임의 좌표로 길찾기하지 않고, 집 좌표와 REST API 키는 브라우저에 보내지 않는다. 도로 경로의 첫 지점이 집 근처라 대략적인 위치는 드러난다.
- 집에서 지역까지 도로 경로가 없으면(카카오가 경로 없음으로 응답, 예: 차량 배편이 없는 섬) 그 구간만 직선으로 잇는다. 배편 경로는 카카오가 일반 경로로 주므로 그대로 그린다(2026-10-28 서울→제주시·울릉도 호출로 확인: 둘 다 성공 응답, "페리항로" 구간 좌표가 촘촘히 오고 거리·시간에 배편이 포함됨). 직선의 출발점은 집 좌표를 약 110m 단위로 흐려 보내고, 자동차 경로가 아니므로 거리·시간 합계에서 빼고 화면에 그 사실을 적는다. 장소 사이 구간은 직선으로 대체하지 않고 다시 시도·건너뛰기를 보여 준다.
- 길찾기는 집 → 지역 1건과, 배지를 누를 때마다 "지금 있는 곳 → 누른 장소" 1건만 부른다(장소 4곳을 다 들르면 5건). 장소 조합을 미리 받지 않으며, 배지에 손가락이 닿는 순간 요청을 시작해 기다림을 줄인다. 앞 구간이 진행 중이라 출발점이 정해지지 않은 장소는 차례가 오면 부른다. 받은 경로는 화면에 있는 동안 TanStack Query에 캐싱해(`staleTime`·`gcTime` 무한) 다시 보기에 재사용하고, 화면을 나가면 지운다. 기록 수정은 다른 화면에서 하므로 돌아오면 경로를 새로 받고, 이어 보기는 기록 데이터 재조회가 끝난 뒤 시작해 바뀐 장소를 쓴다. 카카오 데브톡에 "실시간이 아닌 임시 캐싱 등의 방법으로 API 호출 및 이용은 금지"라는 답변(공식 여부·근거 조항 미확인)이 있어 운영 전에 카카오에 확인한다.
- 자동차 길찾기 무료 제공량은 하루 10,000건이다(2026-10-28 요금 페이지 기준). 다중 목적지 길찾기는 거리·시간 요약만 주고 도로 좌표가 없어 선을 그릴 수 없고, 다중 경유지 길찾기는 누를 순서를 미리 알 수 없어 맞지 않는다.
- 경로를 불러오는 중이라는 표시는 앱 토스트로 띄우지 않는다. 앱 토스트는 결과 알림용(자동으로 사라지고 로딩·직접 닫기가 없음)이고, 재시도·건너뛰기처럼 동작이 필요한 실패는 화면 안에 두는 것이 앱 규칙이다.

## 확인할 것

- 로컬에 Docker/Podman이 없어 로컬 Supabase에서 마이그레이션과 RLS 실행 검증을 하지 못했다. 실제 사용자 세션 사이의 접근 차단은 따로 통합 검증한다.
- 실제 계정과 기기에서 주소 등록, 지역별 기록 목록, 경로 재생, 터치 제스처를 확인한다.

## UX 개선 백로그

- 2026-10-28 점검에서 나온 항목(겹친 점 선택, URL로 이어 보기, 섬 직선 연결, 터치 영역, 버튼 컴포넌트, 지역 확대 제거, 배지 다시 누르기, 진입 애니메이션, 배지 줄 흐림, 확대 시 지역 이름, 빈 상태 버튼)은 모두 반영했다. 지금 보는 기록은 기록 읽기로 상세 시트를 열어 확인한다.
