# 독립 기록 지도 구현

- 경로: `/journey` (`app/(service)/(app)/journey`). 기존 홈(`/`)과 프로토타입(`/prototypes/travel`)을 교체하지 않는다. 다른 상세 화면과 같은 공통 레이아웃(최대 `--app-width` 폭, 고정 뒤로가기 `PageBackButton`, 하단 탭 없음)과 앱 공용 쿼리 클라이언트·토스트를 쓴다.
- 기존 프로토타입의 구현 당시 동작은 [현황 문서](travel-prototype-current.md), 합의한 동작은 [장소 연결 계획](travel-route-interaction.md)에 기록했다.

## 화면과 데이터

- 로그인과 현재 사용자 선택이 필요하다. 방문 지역 노드 또는 지역 목록에서 지역을 선택하면 홈 지도 시트와 같은 기록 목록(`RegionRecordList`, 미니 지도·시·군·구 칩 포함)을 보여 준다. 데이터도 홈과 같은 `recordLocationsQueryOptions` 캐시를 공유하며, 별도의 15개 단위 기록 API는 두지 않는다. 지역 시트들, 기록 읽기 상세 시트와 그 안의 삭제 확인 창은 앱 테마와 상관없이 다크 토큰(`.dark` 하위 영역)으로 칠한다.
- 기록을 열면 목록을 닫고 설정에 저장한 현재 사용자의 집에서 기록에 저장된 지역 좌표까지 카카오 자동차 추천 경로를 조회해 흰색 선으로 그린다. 설정에서 카카오 주소 찾기로 주소를 선택해 등록·변경하거나 삭제할 수 있다.
- 도착한 지점은 초록색 점과 파동으로, 이전 지점은 흰색으로 표시한다. 장소 배지를 고른 순서대로 구간을 추가하고 기존 선을 유지한다. 빠르게 선택한 장소는 대기열에서 순서대로 처리한다. 배지에는 대기·이동 중 상태를 표시하지 않는다. 장소 구간이 이미 화면 위쪽에 충분한 크기로 보이면 지도를 움직이지 않고, 너무 작거나(긴 집 출발 구간 직후) 화면 밖이면 그 구간에 맞춰 확대·이동한다. 구간은 상단 제목·버튼과 하단 정보에 가리지 않도록 화면 위에서 45% 지점을 중심으로 맞춘다.
- 조회 실패 시 현재 위치와 이전 구간을 유지하며 재시도하거나 해당 장소를 건너뛴다. 다시 보기는 성공한 장소를 처음부터 순서대로 다시 그리며, 캐시에 남은 구간은 호출 없이 그린다. 상단 고정 툴바 오른쪽에는 "…" 버튼 하나를 두고, 누르면 오른쪽 끝에 붙은 채 왼쪽으로 늘어나며(열 때만 스프링 반동, iOS 26 Liquid Glass 툴바 메뉴 참고) 전체 경로 보기·다시 보기·이 지역 기록 목록·전국 지도로 돌아가기 아이콘이 나타난다. 동작을 고르거나 바깥을 누르거나 Escape로 닫힌다. 지역명 제목 아래에는 기록 읽기를 두고 하단에는 방문 장소 배지와 거리·시간만 둔다. 출발점은 이름 대신 집 아이콘으로 표시한다.
- 성공한 구간의 거리와 예상 자동차 시간을 합산한다. 경로와 소요 시간은 조회 시점의 추천 결과이며 실제 이동 경로나 방문 순서를 뜻하지 않는다. 기록 읽기는 기록 목록 달력과 같은 기록 상세 바텀 시트(`widgets/record-detail`)를 연다.
- 지도 조작은 진행 중인 선 재생을 멈추지 않는다. 드래그, 두 손가락 핀치, 마우스 휠로 이동·확대·축소하며 화면 확대·축소 버튼과 출처 정보 버튼은 두지 않고, 지도·경로 출처는 설정 화면 하단에 표시한다. 모션 줄이기를 반영한다.

## 집 주소와 보안

- `member_home_addresses`는 계정 소유자와 현재 사용자의 조합을 키로 사용한다. 한 계정에 여러 사용자가 있어도 각자의 출발지를 따로 저장한다. 같은 계정을 사용하는 구성원들은 계정 소유자 권한을 공유하며 서로의 주소를 완전히 분리하는 보안 경계는 아니다.
- RLS는 로그인 계정의 소유 데이터만 허용하고 멤버가 해당 계정에 속하도록 복합 외래 키로 검사한다. 사용자가 선택한 주소 문자열만 저장하며, 주소 좌표는 저장하지 않고 주소 확인 및 집 출발 구간을 요청할 때 카카오 주소 검색으로 변환한다.
- 길찾기 서버는 기록 소유자와 지역·장소의 기록 연결을 확인한다. 브라우저에서 임의 출발·도착 좌표를 받아 길찾기하지 않으며 REST API 키는 서버에만 둔다.
- 길찾기 경로는 사용자 판단에 따라 TanStack Query에 구간(기록·지역·목적지·출발지)별로 캐싱한다. 앱 공용 쿼리 클라이언트에 두되 `/journey` 화면을 나갈 때 경로 캐시를 지워(예: 설정에서 집 주소 변경) 다시 들어오면 새로 조회하고, 쓰이지 않은 구간은 기본 gcTime(5분) 뒤 지워진다. 실패한 구간은 자동 재시도하지 않고 재시도 버튼으로 다시 조회한다. 카카오 데브톡에 실시간이 아닌 임시 캐싱을 금지한다는 답변(공식 여부·근거 조항 미확인)이 있으므로 운영 전에 카카오에 확인한다.
- 기록을 누르는 순간(pointerdown) 집 출발 구간 조회를 시작하고, 클릭 시 같은 조회에 합류한다. 기록을 열면 지역 → 각 장소, 장소 ↔ 장소 양방향 경로를 한 번에 미리 조회해(앞의 6개 장소, 최대 36건) 배지를 누를 때는 호출 없이 바로 그린다. 7번째 이후 장소가 걸린 구간은 누를 때 조회한다. 배지는 누르는 즉시 선택(초록) 표시하고, 선택한 배지는 모두 선택 상태를 유지한다. 이미 선택한 배지(그려진 곳·그리는 중·대기 중)는 다시 눌러도 아무 동작을 하지 않으며, 이전 장소로 되돌아가는 구간은 만들지 않는다. 거리와 시간은 선이 그려지는 900ms 동안 함께 올라간다. 선택한 배지는 취소하지 않고 모두 대기열에 넣어 그린다. 모바일 전용이라 마우스 전용 처리는 두지 않는다. 서버는 기록 조회와 집 주소 조회·좌표 변환을 동시에 진행한다. 보이는 기록 목록의 집 출발 구간은 미리 조회하지 않는다.

## 적용 및 검증 상태

- 기록 변환·장소 대기열·시간 표시 관련 테스트 7개, 타입 검사와 프로덕션 빌드를 통과했다. Biome 검사도 통과했으며 기존 `record-detail-sections.tsx`의 배열 인덱스 key 경고 2개가 남아 있다.
- 집 주소 테이블과 권한 정리 마이그레이션을 연결된 DB에 적용했다. RLS 활성화, 소유자 정책 및 authenticated 역할의 CRUD 권한을 확인했다.
- 로컬 환경에 Docker/Podman이 없어 로컬 Supabase에서 마이그레이션과 RLS 실행 검증은 하지 못했다. 실제 사용자 세션 간 접근 차단은 별도 통합 검증이 필요하다.
- 실제 계정에서 주소 저장, 홈 지도와 공유하는 지역별 기록 목록, 경로 재생 및 모바일·웹 제스처를 통합 검증해야 한다. 특히 카카오 주소 및 자동차 길찾기 사용 조건과 요청량은 운영 적용 전에 확인한다.

## 흐름 보완

- 지역 시트나 기록 목록을 기록을 열지 않고 닫으면 전국 지도로 돌아간다. 기록을 보는 중에 목록을 닫으면 지도와 선을 그대로 둔다.
- 집 주소가 없으면 기록 목록 대신 안내와 설정 이동 버튼을 보여 주고 기록을 불러오지 않는다.
- 경로 조회 중 안내는 하단 패널 위에 떠 있는 표시로만 보여 배지와 거리가 움직이지 않게 한다. 앱 토스트는 결과 알림용(자동으로 사라짐, 로딩·직접 닫기 없음)이고 재시도·건너뛰기 같은 동작이 필요한 실패는 화면 안에 두는 규칙이라 토스트를 쓰지 않았다.
- 다시 보기는 지금까지 고른 장소(그리는 중·대기 중 포함)를 누른 순서대로 다시 그리고, 그동안 상단 동작 버튼과 기록 읽기는 사라졌다가 끝나면 다시 나타난다.
- 상세 시트에서 기록을 삭제하면 전국 지도로 돌아가고 지역 점을 새로 고친다.
- 지도 제목은 기록 목록 시트 제목과 같은 "○○의 기억"을 쓴다. 하단 그라데이션 위에서도 지도를 끌고 확대할 수 있다.
- 전국 지도는 홈 지도(HOME_FRAME)와 같은 경위도 범위(동경 125.5~130.2°, 북위 32.4~39.4°)로 맞춰 본토와 제주가 가운데 오고, 서쪽 백령도와 동쪽 울릉도·독도는 바깥에 두어 축소하면 보인다. 경계 데이터에 독도가 없어 동도·서도를 작은 점으로 직접 그린다. 출발점의 집 아이콘은 점 바로 위 가운데에 둔다.
