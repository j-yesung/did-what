# 독립 기록 지도 구현

- 경로: `/journey`. 기존 홈(`/`)과 프로토타입(`/prototypes/travel`)을 교체하지 않는다.
- 기존 프로토타입의 구현 당시 동작은 [현황 문서](travel-prototype-current.md), 합의한 동작은 [장소 연결 계획](travel-route-interaction.md)에 기록했다.

## 화면과 데이터

- 로그인과 현재 사용자 선택이 필요하다. 방문 지역 노드 또는 지역 목록에서 지역을 선택하면 기록 목록을 15개씩 가져온다. 더 보기를 누를 때 다음 목록을 불러오며, 기록 목록에 TanStack Query를 사용한다.
- 기록을 열면 목록을 닫고 설정에 저장한 현재 사용자의 집에서 기록에 저장된 지역 좌표까지 카카오 자동차 추천 경로를 조회해 흰색 선으로 그린다. 설정에서 카카오 주소 찾기로 주소를 선택해 등록·변경하거나 삭제할 수 있다.
- 도착한 지점은 초록색 점과 파동으로, 이전 지점은 흰색으로 표시한다. 장소 배지를 고른 순서대로 구간을 추가하고 기존 선을 유지한다. 빠르게 선택한 장소는 대기열에서 순서대로 처리한다.
- 조회 실패 시 현재 위치와 이전 구간을 유지하며 재시도하거나 해당 장소를 건너뛴다. 다시 보기는 성공한 장소를 처음부터 순서대로 재조회한다. 전체 경로 보기와 전국 지도로 돌아가기를 제공한다.
- 성공한 구간의 거리와 예상 자동차 시간을 합산한다. 경로와 소요 시간은 조회 시점의 추천 결과이며 실제 이동 경로나 방문 순서를 뜻하지 않는다. 메모가 있는 기록은 확장형 바텀 시트로 읽는다.
- 지도 조작은 진행 중인 선 재생을 멈추지 않는다. 마우스 휠, 드래그와 화면의 확대·축소 버튼을 제공하며 모션 줄이기를 반영한다.

## 집 주소와 보안

- `member_home_addresses`는 계정 소유자와 현재 사용자의 조합을 키로 사용한다. 한 계정에 여러 사용자가 있어도 각자의 출발지를 따로 저장한다. 같은 계정을 사용하는 구성원들은 계정 소유자 권한을 공유하며 서로의 주소를 완전히 분리하는 보안 경계는 아니다.
- RLS는 로그인 계정의 소유 데이터만 허용하고 멤버가 해당 계정에 속하도록 복합 외래 키로 검사한다. 사용자가 선택한 주소 문자열만 저장하며, 주소 좌표는 저장하지 않고 주소 확인 및 집 출발 구간을 요청할 때 카카오 주소 검색으로 변환한다.
- 길찾기 서버는 기록 소유자와 지역·장소의 기록 연결을 확인한다. 브라우저에서 임의 출발·도착 좌표를 받아 길찾기하지 않으며 REST API 키는 서버에만 둔다.
- 카카오 길찾기 응답의 사전 조회·일반적인 캐싱/재사용 허용 범위는 확인되지 않았다. 기록 목록과 달리 경로를 미리 조회하거나 TanStack Query에 보관하지 않으며 다시 보기는 재조회한다.

## 적용 및 검증 상태

- 집 주소 테이블과 권한 정리 마이그레이션을 연결된 DB에 적용했다. RLS 활성화, 소유자 정책 및 authenticated 역할의 CRUD 권한을 확인했다.
- 로컬 환경에 Docker/Podman이 없어 로컬 Supabase에서 마이그레이션과 RLS 실행 검증은 하지 못했다. 실제 사용자 세션 간 접근 차단은 별도 통합 검증이 필요하다.
- 실제 계정에서 주소 저장, 지역별 15개 목록, 경로 재생 및 모바일·웹 제스처를 통합 검증해야 한다. 특히 카카오 주소 및 자동차 길찾기 사용 조건과 요청량은 운영 적용 전에 확인한다.
