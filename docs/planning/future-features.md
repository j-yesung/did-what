# 향후 기능 백로그

연인·친구 등 함께한 사람과 언제, 어디서, 무엇을 했는지 기록하고 돌아보는 관계 기반 라이프로그를 기준으로 정리한다. iOS 홈 화면에 설치한 PWA를 우선 고려하되, 일반 브라우저에서도 핵심 기록 기능은 사용할 수 있어야 한다.

- 갱신일: 2026-09-23
- 아래 우선순위는 개발 순서 제안이며 확정된 출시 일정은 아니다.
- 구현을 마친 항목은 삭제하고 이력은 Git에서 확인한다. 지도 핀치 확대·이동, 현재 위치·복귀, 댓글, 새 기록·댓글 푸시는 기존 기능으로 보고 확장만 다룬다.

## 먼저 검토할 기능

### 1. 작성 중인 기록 임시 저장·복구

- 목적: 사진을 고르거나 다른 앱으로 이동한 뒤 PWA가 종료돼도 작성하던 추억을 이어 쓴다.
- 첫 범위: 날짜, 지역, 장소, 활동, 메모를 이 기기에 자동 저장하고 재진입 시 이어 쓰기·버리기를 제공한다. 서버 저장 완료 후 초안을 지운다.
- 계정·현재 구성원별로 초안을 구분하고, 로그아웃 시 처리 방침을 정한다. 다른 계정의 초안을 복구하면 안 된다.
- 임시 저장과 서버 저장을 구분해 표시한다. 기기 저장 공간이 지워지면 복구할 수 없는 로컬 초안을 백업으로 안내하지 않는다.
- 오프라인에서는 기존 입력을 보존하는 것부터 시작한다. 앱이 닫힌 동안 자동 업로드되는 기능은 별도 단계다.

### 2. 기록별 함께한 사람과 사람별 발자취

- 목적: “누가 작성했지?”뿐 아니라 “그날 누구와 함께했지?”로 추억을 찾는다.
- 첫 범위: 현재 계정의 구성원 중 함께한 사람을 선택하고, 사람별 기록 목록과 방문 지역을 보여준다. 작성자와 동행자는 별개로 취급한다.
- 기존 기록은 동행자 미지정 상태로 유지한다. 작성자나 전체 구성원을 동행자로 자동 추정하지 않는다.
- 구성원 이름 변경·비활성화 후에도 과거 기록의 연결은 유지한다.
- 계정 밖 사람의 이름만 기록하는 기능, 별도 계정 초대, 관계별 공간은 후속 검토한다. 동행자 선택만으로 조회·수정 권한이 생기지는 않는다.

### 3. 기록 사진과 대표 사진

- 목적: 글과 지도만으로 떠올리기 어려운 순간을 사진으로 기억한다.
- 첫 범위: 사용자가 고른 사진 첨부, 미리보기, 순서 변경, 대표 사진과 삭제를 제공한다. 업로드 중·실패·재시도 상태를 구분한다.
- iOS 사진 선택 흐름과 HEIC 등 실제 입력 형식을 확인하고 파일 수·용량 제한, 이미지 축소, 저장 비용을 정한다.
- 사진은 기록과 같은 공개 범위를 따른다. 촬영 위치 등 EXIF 정보는 필요 없이 노출하지 않는다.
- 날짜·위치 추출은 나중에 입력 제안으로만 제공한다. 사용자가 확인하기 전에 기록 값을 덮어쓰지 않는다.

### 4. 그날의 추억과 월별 돌아보기

- 목적: 기록을 쌓는 데서 끝나지 않고 다시 열어볼 이유를 만든다.
- 첫 범위: 앱 안에서 작년 오늘의 기록과 이번 달 기록·방문 지역을 보여주고 원래 기록으로 이동한다. 기록이 없으면 억지로 회고 카드를 만들지 않는다.
- 사람별 회고는 동행자 연결 후 추가한다. 사진 기능이 생기면 대표 사진을 활용한다.
- 여러 지역을 가진 하나의 기록은 기록 수에서 한 번만 세고, 방문 지역은 중복 없이 센다.
- 기록이 며칠에 걸친 경우 회고 기준일을 먼저 정한다. 경쟁 순위·연속 작성 압박보다 함께한 순간을 보여주는 데 집중한다.

### 5. 지도에서 추억으로 연결

- 목적: 지도에서 눈에 띈 지역을 바로 열어 그곳의 기록을 돌아본다.
- 첫 범위: 셀 탭 → 해당 지역의 기록 수·최근 방문 요약을 바텀 시트에서 제공한다. 핀치·드래그가 끝난 동작을 탭으로 처리하지 않는다.
- 기간 필터를 지도와 기록 목록에 함께 적용한다. 동행자 기능 이후 사람 필터도 연결한다.
- 작은 셀을 정확히 누르기 어려운 경우 지도를 확대하거나 지역 배지로 같은 정보를 찾을 수 있게 한다.
- 지도는 기존 대한민국 활동 지도를 유지한다. 거리·길찾기가 필요한 장소 화면에서만 별도 지도 도입을 검토한다.

### 6. 기억을 잃지 않기 위한 복구·내보내기

- 목적: 실수로 지운 기록을 되찾고, 오래 쌓은 개인 기록을 앱 밖에도 보관한다.
- 첫 범위: 휴지통과 복구를 제공한다. 보관 기간, 영구 삭제 확인, 연결된 댓글·사진의 복구 및 삭제 범위를 함께 정한다.
- 내보내기는 날짜·활동·메모·함께한 사람·지역·장소를 포함한 파일부터 시작한다. 사진이 추가되면 사진 원본과 연결 정보도 보관할 수 있도록 확장한다.
- 파일 생성·다운로드·공유 실패 시 재시도할 수 있게 한다. 가져오기와 다른 서비스 이전은 파일 형식이 정리된 뒤 검토한다.

## PWA에서 필요한 사용 경험

### 설치와 알림 안내

- 첫 기록을 저장한 뒤처럼 필요를 느낄 시점에 홈 화면 추가를 안내한다. 자동 설치를 약속하거나 방문 때마다 반복하지 않는다.
- iOS에서는 홈 화면 추가 절차를 안내하고, 설치 프롬프트를 지원하는 브라우저에서는 사용자 버튼으로 호출한다. 이미 앱 모드로 실행 중이면 설치 안내를 숨긴다. [설치 동작 참고](https://web.dev/learn/pwa/installation)
- 기존 새 기록·댓글 푸시에 알림 종류별 켜기·끄기를 추가한다. iOS Web Push는 16.4 이상 홈 화면 웹 앱에서 사용자 동작으로 권한을 요청하는 흐름을 기준으로 한다. [WebKit Web Push 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
- 리마인더는 서버 예약 발송으로 설계하고 정확한 시각의 수신을 보장하지 않는다. 앱을 다시 열면 앱 내 회고·알림에서도 내용을 확인할 수 있게 한다.

### 오프라인과 업데이트

- 1단계: 연결 끊김 안내, 작성 초안 보존, 재연결 후 사용자가 저장을 재시도하는 흐름.
- 2단계: 최근 열어본 기록과 지도 데이터를 제한적으로 저장해 읽기 제공. 저장된 범위와 마지막 갱신 시각을 표시한다.
- 3단계: 오프라인 작성 대기 목록. 앱을 다시 열거나 연결이 복구됐을 때 전송하고 중복 저장·수정 충돌을 처리한다. iOS를 포함한 전체 지원 환경에서 Background Sync를 전제로 삼지 않는다. [Background Sync 지원 범위](https://developer.mozilla.org/en-US/docs/Web/API/Background_Synchronization_API)
- 기기 저장소는 용량·삭제 정책의 영향을 받으므로 영구 보관소로 취급하지 않는다. 계정별로 캐시를 구분하고 로그아웃 시 개인 기록 캐시를 정리한다. [WebKit 저장소 정책](https://webkit.org/blog/14403/updates-to-storage-policy/)
- 오프라인 캐싱 도입 시 새 버전 안내와 캐시 갱신 정책을 함께 마련한다. 작성·업로드 중 강제 새로고침으로 입력이 사라지지 않게 한다.

### 사진·공유·위치의 대체 흐름

- 공유는 사용자 버튼에서 실행하고, 공유 가능한 파일인지 확인한다. 공유 API를 지원하지 않으면 다운로드·링크 복사를 제공한다. [Web Share 명세](https://www.w3.org/TR/web-share/)
- 현재 위치는 사용자가 요청한 순간에만 조회한다. 권한 거절·시간 초과 때도 지역 검색과 직접 선택으로 기록할 수 있게 한다.
- 지도 현재 위치와 주변 장소 검색은 구분한다. 주변 검색을 추가하더라도 지속적인 이동 추적이나 자동 방문 기록으로 확장하지 않는다.
- 실기기 확인에는 홈 화면 실행, 앱 종료·재실행, 권한 거절, 오프라인, 사진 선택 후 복귀, 노치·키보드·드로어가 있는 화면을 포함한다.

## 필요가 확인되면 검토할 후보

### 기록·장소 편의

- 기록 변경 이력과 마지막 수정자 표시
- 여러 기록 일괄 수정·삭제, 목록에서 바로 수정
- 장소 이름 수정, 장소 지도 미리보기, 지도에서 장소 선택
- 현재 위치 기반 주변 장소 검색, 검색 자동완성 또는 입력 중 검색
- 저장 장소 목록 페이지네이션 또는 무한 스크롤
- 실제 거리·주변 탐색 수요가 생기면 Kakao 지도 SDK와 여러 장소 제공자 지원 검토

### 계정과 운영

- 비밀번호 재설정과 계정 복구: 공개 사용자 확대 전에 우선 검토
- 소셜 로그인, 인증 이메일 템플릿 커스터마이징
- 계정 삭제 시 기록·사진·공유 링크·푸시 구독의 처리 안내
- 운영 작업이 실제로 필요할 때 관리자 권한 검토

### UI와 접근성

- 입력 경계와 일반 텍스트 색 대비 재검증과 보정
- 홈 지도에 방문 지역 요약·범례와 보조기기용 지역 정보 제공
- 경로별 문서 제목과 VoiceOver용 버튼 이름·읽기 순서 점검
- 기록 작성 퍼널의 오류 필드가 화면에 보이도록 이동하고 오류 안내
- 입력 placeholder 규칙 통일
- 다크 모드 전용 앱 아이콘은 플랫폼 지원과 실제 필요 확인 후 검토

## 현재 제품 방향에서 제외

- 앱 스토어 배포와 네이티브 래핑(TWA, Capacitor): 현재는 PWA 경험에 집중
- 상시 GPS 추적, 백그라운드 지오펜싱, 자동 이동 경로 수집
- 공개 피드·팔로워·인기 순위 등 불특정 다수 중심 소셜 기능
- 기록 수·방문 수 경쟁, 연속 작성 실패에 대한 압박
- 리 단위 지역 선택
- 숫자로 분할된 행정동 선택

## 기술 도입은 사용자 요구에 맞춰 결정

아래 항목은 독립적인 사용자 기능이나 선행 작업으로 잡지 않는다.

- 기록 실시간 구독: 다른 구성원의 변경을 즉시 봐야 하는 흐름이 확인될 때
- SQL aggregation, view 또는 materialized view: 회고·지도 집계에 측정 가능한 성능 문제가 생길 때
- 개발·데모용 seed 데이터: 회고·대량 기록 검증에 필요한 범위에서
- 과도한 domain abstraction
- 별도 인증 상태 관리 라이브러리
- 별도 전역 상태 관리
- optimistic update의 전면 적용: 현재 사용하는 범위를 넘어 확대할 때는 실패 복구와 사용자 이득을 확인
- 여러 장소 provider를 위한 선행 추상화

## 추천 착수 순서

1. 임시 저장·복구로 작성 안정성을 확보한다.
2. 함께한 사람 연결로 관계 중심 탐색의 기반을 만든다.
3. 사진 첨부와 지도 셀 선택으로 기억을 남기고 찾는 경험을 보강한다.
4. 그날의 추억·월별 돌아보기로 쌓인 기록을 다시 보여준다.
5. 휴지통·내보내기를 보강하고, 오프라인 읽기·선택형 리마인더를 단계적으로 추가한다.

설치 안내는 처음부터 가볍게 제공할 수 있다. 공유 링크와 별도 계정 초대는 공개 범위·권한 정책을 정한 뒤 진행한다.
