# 다음 단계: 기록 검색과 필터

## 목적

기록이 쌓여도 활동 내용, 기간, 함께한 사람, 장소를 기준으로 원하는 추억을 빠르게 찾을 수 있게 한다.

이번 단계는 서버 검색과 필터, URL 상태 유지까지만 구현한다. 페이지네이션과 자동완성은 실제 기록량이 늘어난 뒤 추가한다.

## 완료 조건

- `/records`에서 활동과 메모를 검색할 수 있다.
- 시작일과 종료일로 기록 날짜 범위를 좁힐 수 있다.
- 함께한 사람과 장소를 각각 선택해 필터링할 수 있다.
- 여러 조건을 동시에 적용할 수 있다.
- 검색 조건이 쿼리 파라미터에 유지되어 새로고침과 뒤로가기 후에도 복원된다.
- 조건을 한 번에 초기화할 수 있다.
- 결과가 없으면 현재 조건을 바꾸거나 초기화하도록 안내한다.
- 현재 사용자의 기록·사람·장소만 조회한다.
- 잘못된 날짜와 다른 사용자의 식별자는 안전하게 무시하거나 검증 오류로 처리한다.

## 조회 흐름

1. `searchParams`에서 `q`, `from`, `to`, `personId`, `placeId`를 읽는다.
2. 검색어 길이와 날짜 범위, UUID 형식을 서버에서 검증한다.
3. 인증 사용자의 사람·장소 선택지와 기록 조회를 가능한 범위에서 병렬로 시작한다.
4. `records.owner_id`를 기본 조건으로 두고 유효한 필터만 Supabase 쿼리에 추가한다.
5. 사람 필터는 `record_people` 관계를 통해 적용한다.
6. 결과는 기존과 동일하게 기록일·생성일 최신순으로 정렬한다.

## UI

- 기존 Forest Green 토큰과 모바일 타임라인을 유지한다.
- 검색은 shadcn/ui `Input`, 조건 묶음은 `FieldGroup`과 `Field`를 사용한다.
- 날짜는 네이티브 `input type="date"`, 사람·장소는 기존 `NativeSelect`를 사용한다.
- 검색 실행과 초기화는 기존 `Button` 스타일을 사용한다.
- `Search`, `CalendarDays`, `Users`, `MapPin`, `X`를 `lucide-react`에서 개별 import한다.
- 결과 카드는 기존 기록 목록 컴포지션을 유지한다.
- 직접 SVG나 다른 아이콘 라이브러리를 추가하지 않는다.

## 구조

```text
app → pages → entities → shared
```

- `/records`의 `searchParams` 해석과 화면 조립은 `src/pages/records`에 둔다.
- 조건부 Supabase 쿼리는 기존 `entities/record` 공개 API를 확장한다.
- 검색 폼은 URL 이동만 담당하고 별도 전역 상태를 만들지 않는다.
- 같은 레이어 slice 간 import는 만들지 않는다.

## 제외 범위

- 기록 목록 페이지네이션
- 무한 스크롤
- 입력 중 검색과 자동완성
- 검색어 하이라이트
- 정렬 옵션
- 저장된 검색 조건
- 사진 내용 검색
- 전문 검색 인덱스와 별도 검색 서비스

## 검증

- 검색어 단독 조회
- 날짜 시작·종료·범위 조회
- 사람과 장소 단독 필터
- 검색어·기간·사람·장소 복합 필터
- 조건 없는 전체 기록
- 결과 없는 빈 상태와 필터 초기화
- 잘못된 날짜·UUID
- 다른 사용자의 식별자 접근 차단
- 비로그인 접근 차단
- Biome import/format check
- lint
- TypeScript type check
- production build
