# 다음 단계: 하단 탭 전환 피드백

> 상태: 완료 (2026-08-15)

## 배경

배포 환경에서 하단 탭을 처음 열 때 짧은 대기가 있다. 주요 화면은 사용자 인증과 Supabase 조회가 필요한 동적 라우트라 서버 응답이 오기 전까지 기존 화면에 머물며, 탭을 눌렀는지 바로 알아보기 어렵다.

지연 자체는 길지 않으므로 탭별 스켈레톤이나 keep-alive는 과하다. 모든 탭에 `prefetch={true}`를 지정하면 사용자가 방문하지 않은 화면의 인증과 데이터 조회까지 실행되므로 적용하지 않는다.

## 목표

탭을 누르면 URL과 활성 탭은 즉시 전환하고, 새 화면의 데이터가 준비되는 동안 콘텐츠 영역에 공통 로딩 피드백을 표시한다.

## 구현

1. `app/(app)/loading.tsx`를 추가해 인증된 앱 라우트의 공통 로딩 경계를 만든다.
2. 로딩 화면은 실제 페이지를 흉내 낸 스켈레톤 대신 앱 배경과 작은 `Spinner`만 사용한다. 매우 짧은 전환에서 번쩍이지 않도록 시각적 Spinner는 약 300ms 뒤 나타나게 한다.
3. 상태 문구는 “화면을 불러오는 중”으로 제공해 보조기기에도 전환 상태를 알린다.
4. 하단 내비게이션은 상위 layout에 남겨 두어 로딩 중에도 계속 조작할 수 있게 한다.
5. 탭 `Link`의 기본 프리패치 동작은 유지하며 `prefetch={true}`는 지정하지 않는다.
6. `useLinkStatus`, 별도 `router.prefetch`, 전역 로딩 상태는 추가하지 않는다. 라우트 로딩 경계 하나로 처리한다.

## 동작 기준

- 탭 클릭 직후 URL과 활성 아이콘이 바뀐다.
- 새 페이지의 인증과 Supabase 조회는 실제로 방문한 탭에서만 실행된다.
- 조회 중에는 콘텐츠 영역만 로딩 화면으로 교체되고 하단 내비게이션은 유지된다.
- 조회가 끝나면 별도 애니메이션 없이 실제 페이지가 같은 콘텐츠 영역에 표시된다.
- 로딩 중 다른 탭을 누를 수 있고 앞선 전환이 완료될 때까지 기다리지 않는다.

## 범위 제외

- 탭별 또는 페이지별 스켈레톤
- 모든 탭의 전체 데이터 프리패치
- keep-alive와 React `Activity`
- Next.js `cacheComponents`
- 전역 상태 기반 라우트 로딩 관리
- 페이지네이션과 무한 스크롤

## 완료 조건

- 프로덕션 환경에서 하단 탭 클릭 직후 활성 탭과 로딩 화면이 표시된다.
- 사용자가 누르지 않은 탭의 Supabase 데이터 조회가 실행되지 않는다.
- 로딩 중에도 하단 내비게이션이 보이고 다른 탭으로 이동할 수 있다.
- 로딩 상태가 접근성 트리에서 한국어로 전달된다.
- 짧은 전환에서 로딩 화면이 과도하게 번쩍이지 않는다.

## 검증

1. 프로덕션 빌드를 실행하고 로그인한다.
2. 개발자 도구에서 네트워크 속도를 낮춘다.
3. 하단 탭을 눌러 URL, 활성 아이콘, 로딩 화면 순서가 즉시 반영되는지 확인한다.
4. Network에서 클릭하지 않은 탭의 Supabase 요청이 발생하지 않는지 확인한다.
5. 로딩 중 다른 탭을 눌러 마지막으로 선택한 화면이 정상적으로 열리는지 확인한다.
