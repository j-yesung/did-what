# 다음 단계: 장소 상세와 이곳의 기록

## 목적

저장한 장소를 선택해 장소 정보와 그곳에서 남긴 기록을 시간순으로 돌아볼 수 있게 한다.

이번 단계는 장소 상세 조회와 관련 기록 이동까지만 구현한다. 장소 수정·삭제나 지도 미리보기는 실제 필요가 생긴 뒤 추가한다.

## 완료 조건

- 저장한 장소 목록에서 `/places/[placeId]`로 이동할 수 있다.
- 상세 화면에 장소명, 주소, 저장일이 표시된다.
- 해당 장소에 연결된 현재 사용자의 기록만 최신순으로 표시된다.
- 기록 카드에서 기존 `/records/[recordId]` 상세 화면으로 이동할 수 있다.
- 관련 기록이 없으면 다음 행동을 안내하는 빈 상태를 표시한다.
- 잘못된 UUID와 다른 사용자의 place ID는 동일하게 404 처리한다.
- 목록과 상세 조회 오류를 사용자에게 안전한 한국어 메시지로 표시한다.

## 조회 흐름

1. `placeId` UUID 형식을 먼저 확인한다.
2. `getUser()`로 인증 사용자를 확인한다.
3. `places.id`, `places.owner_id`로 현재 사용자의 장소 한 곳을 조회한다.
4. 같은 `place_id`를 가진 현재 사용자의 records를 최신 날짜순으로 조회한다.
5. 장소 정보와 기록 목록은 독립 쿼리로 동시에 시작한다.
6. 다른 사용자 데이터는 RLS와 owner 필터로 이중 차단한다.

## UI

- 기존 Forest Green 토큰과 모바일 화면 구성을 유지한다.
- 저장한 장소 카드에 `ChevronRight`와 `이곳의 기록 보기` 텍스트 링크를 추가한다.
- 상세 상단은 `MapPinned` 또는 `MapPin`으로 장소를 식별한다.
- 장소명, 주소, 저장일을 한 Card 안에서 읽기 쉽게 배치한다.
- 관련 기록은 기존 기록 목록의 날짜·활동·메모 표현을 유지한다.
- `MapPin`, `CalendarDays`, `NotebookPen`, `ChevronRight`를 `lucide-react`에서 개별 import한다.
- 빈 상태와 오류는 기존 shadcn/ui `Empty`, `Alert`를 사용한다.
- 직접 SVG나 다른 아이콘 라이브러리를 추가하지 않는다.

## 구조

```text
app → pages → entities → shared
```

- `app/(app)/places/[placeId]/page.tsx`는 화면 re-export만 둔다.
- 조회와 화면 조립은 `src/pages/place-detail`에 둔다.
- 장소 단건과 관련 기록 조회는 기존 `entities/place` 공개 API에 최소한으로 추가한다.
- 같은 레이어 slice 간 import는 만들지 않는다.

## 제외 범위

- 장소 이름·주소 수정
- 장소 삭제
- 장소 지도 미리보기
- 외부 지도 길찾기
- 장소별 기록 통계
- 현재 위치 기반 주변 장소 검색
- 기록 검색·필터·페이지네이션
- 무한 스크롤
- 실시간 동기화

## 검증

- 관련 기록이 있는 장소 상세
- 관련 기록이 없는 장소 빈 상태
- 기록 상세 링크 이동
- 존재하지 않는 UUID
- 다른 사용자의 place ID 접근 차단
- 비로그인 접근 차단
- Biome import/format check
- lint
- TypeScript type check
- production build
