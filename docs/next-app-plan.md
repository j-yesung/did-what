# 다음 단계: 지역 중심 기록 모델 전환

> 상태: 구현 및 원격 개발 DB 적용 완료 (2026-08-12)

## 목적

기록의 필수 위치를 특정 장소 1개에서 법정동·읍·면 1개로 전환한다. 특정 장소는 같은 지역 안에서 여러 곳을 선택할 수 있는 선택 정보로 바꾸고, 방문 장소와 내 장소 저장을 분리한다.

기존 개발 데이터는 초기화한다. 현재 미커밋 상태의 단일 장소 등록 Dialog는 새 흐름에 맞게 교체하며 그대로 확장하지 않는다.

## 완료 조건

- 지역명을 검색하면 정규화된 법정동·읍·면 목록이 제시된다.
- 사용자는 목록에서 지역 하나를 반드시 선택해야 기록할 수 있다.
- 숫자 분할 행정동과 리는 선택지에 나오지 않는다.
- 한 기록에 같은 지역의 방문 장소를 여러 개 연결할 수 있다.
- 장소를 먼저 선택하면 첫 장소의 지역이 자동 선택된다.
- 지역이 선택된 뒤에는 같은 지역의 장소만 추가할 수 있다.
- 방문 장소마다 내 장소 저장 여부를 별도로 선택할 수 있다.
- 장소 저장 해제는 기록 연결을 삭제하지 않는다.
- 기록 목록과 상세는 지역을 장소보다 우선해 표시한다.
- 홈 지도는 기록 지역의 대표 좌표를 사용한다.
- 하단 내비게이션에서 장소 탭으로 이동할 수 있다.
- 장소 탭에는 명시적으로 저장한 장소만 표시된다.

## 1단계: 지역 기준 데이터 확정 — 완료

1. Kakao Local API의 주소 검색 결과에서 법정구역 코드가 있는 동·읍·면만 사용한다.
2. 숫자 분할 행정동과 리는 제외한다.
3. 좌표→행정구역 변환으로 장소와 지역 일치를 서버에서 검증한다.
4. 읍·면 하위 코드가 반환되면 법정 읍·면 코드로 정규화한다.
5. 지역 코드, 전체 표시명, 대표 좌표를 기록에 스냅샷으로 저장한다.

검증:

- `망원` 검색 결과에 `서울특별시 마포구 망원동`이 나온다.
- `망원1동`, `망원2동`과 리 단위 결과는 나오지 않는다.
- 동이 없는 지역은 애월읍, 봉평면처럼 읍·면으로 검색된다.
- 같은 검색 응답의 지역 코드는 중복 제거되고 좌표는 API 응답의 유효 숫자만 사용된다.

## 2단계: DB 스키마 초기화와 재구성 — 완료

1. 개발 데이터 초기화를 전제로 새 migration을 작성한다.
2. 별도 지역 마스터 테이블 없이 검증된 지역 스냅샷을 기록에 보관한다.
3. `records.place_id`를 제거하고 지역 코드·이름·대표 좌표를 필수로 둔다.
4. `record_places` N:M 연결 테이블을 추가한다.
5. `places.region_code`와 nullable `saved_at`을 추가한다.
6. 사용자·provider·provider_place_id 중복 방지 제약을 유지한다.
7. `record_people`, `record_places`의 소유권과 지역 일치 조건을 DB 함수에서 검증한다.
8. 기록 생성·수정 DB 함수를 지역과 복수 장소 입력에 맞게 교체한다.
9. RLS와 삭제 정책을 새 관계에 맞게 다시 검증한다.
10. 원격 개발 DB에 migration을 적용하고 Supabase TypeScript 타입을 다시 생성한다.

검증:

- 다른 사용자의 지역 외 데이터에 접근할 수 없다.
- 다른 사용자의 사람·장소를 기록에 연결할 수 없다.
- 기록 지역과 다른 장소를 연결할 수 없다.
- 동일 장소를 한 기록에 중복 연결할 수 없다.
- 저장 해제한 장소도 기존 기록 연결은 유지된다.
- Supabase DB lint에 새 스키마 경고가 없다.

## 3단계: 지역 검색 기능 — 완료

1. 지역 검색어 길이와 형식을 서버에서 검증한다.
2. Kakao 주소 검색에서 전체 표시명과 지역명 후보를 가져온다.
3. 결과는 전체 경로를 표시하고 지역 코드로 선택한다.
4. 자유 텍스트가 남아 있거나 존재하지 않는 코드는 제출하지 못하게 한다.
5. 지역 선택 UI는 shadcn/ui의 기존 입력·Dialog 또는 Combobox 패턴을 사용한다.
6. 검색 아이콘은 `lucide-react`의 `Search`, 지역 아이콘은 `MapPinned` 또는 `MapPin`을 사용한다.

검증:

- 한글 부분 검색
- 중복 지역명의 전체 경로 구분
- 검색 결과 없음
- 잘못되거나 폐기된 지역 코드 제출 차단
- 키보드 조작과 스크린 리더 레이블

## 4단계: 새 기록과 수정 UX 전환 — 완료

1. `어디서`를 필수 `어느 지역에 갔나요?` 필드로 교체한다.
2. 지역 선택 아래에 선택 사항인 방문 장소 검색을 둔다.
3. 지역 미선택 상태에서는 전국 장소를 검색하고, 지역 선택 뒤에는 지역명을 장소 검색어와 함께 사용한다.
4. 선택한 장소의 좌표를 서버에서 법정구역 코드로 변환해 지역 일치를 검증한다.
5. 방문 장소를 여러 개 추가·제거할 수 있게 한다.
6. 선택한 장소별로 `내 장소에 저장`을 제공한다.
7. 이미 저장된 장소는 `저장됨`으로 표시하고 기록 폼에서는 저장 해제하지 않는다.
8. 지역이 없을 때 첫 장소를 고르면 장소의 지역을 자동 선택한다.
9. 방문 장소가 있는 상태에서 지역 변경 시 기존 장소 해제 확인 Dialog를 표시한다.
10. 생성과 수정 모두 동일한 검증 규칙을 사용한다.

검증:

- 지역만 있는 기록 생성
- 지역과 방문 장소 여러 개가 있는 기록 생성
- 일부 방문 장소만 내 장소로 저장
- 다른 지역 장소 추가 차단
- 첫 장소로 지역 자동 선택
- 지역 변경 취소와 확인
- 기록 수정 시 저장 장소가 의도치 않게 해제되지 않음
- 제출 중 중복 실행 방지와 오류 포커스

## 5단계: 기록 조회 화면 전환 — 완료

1. 기록 목록 카드에 지역 전체 경로 또는 문맥에 맞는 축약명을 우선 표시한다.
2. 기록 상세에 지역과 방문 장소 목록을 분리해 표시한다.
3. 저장하지 않은 방문 장소도 기록 상세에서 확인할 수 있게 한다.
4. 기록 상세에서 저장하지 않은 장소를 내 장소로 저장할 수 있게 한다.
5. 장소 상세의 연결 기록 조회를 `record_places` 기준으로 바꾼다.
6. 사람 상세와 기존 기록 조회가 새 관계에서도 유지되는지 확인한다.

## 6단계: 장소 탭과 내비게이션 — 완료

1. 하단 탭을 `지도 → 기록 → 장소 → 사람 → 설정` 순서로 바꾼다.
2. 장소 탭은 `saved_at IS NOT NULL`인 장소만 조회한다.
3. 장소 탭에서 Kakao 장소를 직접 검색해 저장할 수 있게 한다.
4. 장소 저장 해제는 `saved_at`만 비우고 기록 연결은 유지한다.
5. 현재 `/places`와 장소 상세 화면을 새 저장 의미에 맞게 문구와 빈 상태를 수정한다.
6. 5개 탭의 활성 배경 너비와 모바일 레이블 가독성을 확인한다.

## 7단계: 홈 지도 집계 전환 — 완료

1. 지도 조회에서 장소 join을 제거하고 `records.region_code`와 지역 대표 좌표를 가져온다.
2. 기존 최근접 격자 셀 계산을 재사용한다.
3. 같은 지역 기록이 같은 셀에 누적되는지 확인한다.
4. 같은 셀에 여러 지역이 들어오면 합산 농도를 표시한다.
5. 빈 상태 문구를 장소가 아닌 지역 중심으로 수정한다.

지도 셀 클릭, 툴팁, 확대와 이동은 이번 단계에서 구현하지 않는다.

## 8단계: 문서와 전체 검증 — 완료

1. 스키마와 사용자 흐름을 `app-plan.md`와 결과 문서에 반영한다.
2. 과거의 장소 1개 필수 문구를 코드와 문서에서 제거한다.
3. Biome import/format check를 실행한다.
4. 단위 테스트와 TypeScript 검사를 실행한다.
5. production build를 실행한다.
6. 지역 검색, 복수 장소 선택, 5개 탭은 production build 기준으로 확인하고 실제 로그인 브라우저 점검은 후속 수동 확인으로 남긴다.

## 제외 범위

- 지도 확대와 이동
- 지도 셀 클릭과 지역 상세 패널
- 현재 위치 자동 감지
- Kakao에 없는 사용자 정의 장소
- 한 기록에 여러 지역 연결
- 리 단위 지역
- 숫자로 분할된 행정동 선택
- 기록 검색과 필터
- 사진과 Supabase Storage
- 여러 장소 provider

## 완료 후 다음 플랜

지역 중심 기록 모델이 안정화되면 기록 검색과 필터를 지역·사람·기간 기준으로 다시 설계한다. 기존 장소 단일 필터 계획은 그대로 재사용하지 않는다.
