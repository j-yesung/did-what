# 화면 모드 대응과 컬러 토큰 마이그레이션

> 상태: 계획 (2026-08-13)
> `next-app-plan.md`의 PWA 전환이 실기기 점검(4단계)만 남아 있어 별도 문서로 둔다. PWA가 닫히면 이 문서가 다음 계획이 된다.

## 목적

라이트·다크·시스템 설정 세 가지 화면 모드를 지원한다. 그 전에 컬러 토큰을 역할 기반으로 다시 세우고, 브랜드 색을 파랑으로 통일한다.

지금 토큰은 shadcn 기본값을 그대로 쓰고 있어 다크 값을 얹을 자리가 없다. 또한 UI는 초록(`#428C58`)인데 홈 화면 아이콘과 스플래시는 파랑(`#0368F1`)이라 앱을 여는 순간 색이 바뀐다. 시맨틱 토큰이 Base를 가리키는 구조에서는 hue 교체 비용이 사실상 없으므로, 토큰을 다시 세우는 이번 작업에 함께 넣는다.

토스 디자인 시스템(TDS)의 토큰 체계를 참고한다. 핵심은 세 가지다.

- **3단 계층**: Base(원시 색) → Semantic(역할) → Component(요소별)
- **이름 규칙**: `[대상]-[역할]-[변형]`. 대상은 `fill`·`text`·`border`, 역할은 `brand`·`neutral`·`primary`, 변형은 `weak`·`alt`
- **밝기 정렬**: OKLCH 명도를 단계별로 맞춰, `grey-100`과 `blue-100`의 체감 밝기가 같도록 한다. 라이트와 다크는 같은 토큰 이름이 서로 다른 명도값을 가리키는 1:1 대응이다

## 완료 조건

- 앱 UI의 브랜드 색이 홈 화면 아이콘·스플래시와 같은 파랑 계열이다.
- 화면 어디에도 기존 초록이 남아 있지 않다.
- 설정 화면에서 라이트·다크·시스템 중 하나를 고를 수 있다.
- 시스템을 고르면 기기 설정 변경이 새로고침 없이 즉시 반영된다.
- 첫 화면 진입 시 밝은 화면이 번쩍였다가 어두워지는 현상이 없다.
- 선택한 모드가 앱을 껐다 켜도 유지된다.
- 다크에서 본문 대비 4.5:1, 큰 글자·아이콘 3:1을 만족한다.
- 지도 5단계 농도가 다크에서도 서로 구분된다.
- PWA 상태 표시줄 색이 모드에 따라 바뀐다.
- 컴포넌트 파일에 raw hex가 남아 있지 않다.

## 현재 상태

- 토큰이 `:root` 한 곳에 평면으로 있다. 계층이 없다.
- 다크 팔레트가 아예 없다. `@custom-variant dark (&:is(.dark *))` 선언만 있고 `.dark`를 붙이는 코드가 없다.
- `shared/ui`의 6개 파일(button, checkbox, field, input, native-select, textarea)에 shadcn이 넣어둔 `dark:` 유틸이 이미 있다. 지금은 죽어 있는 코드다.
- 커스텀 토큰: `--surface`, `--brand-50~950`(11단계), `--map-empty`·`--map-level-1~4`(5단계).
- `theme-color`는 `#FAFAF8` 고정이다.

## 1단계: 토큰 계층 재정의

1. **Base 레이어**를 만든다. OKLCH로 명도 단계를 맞춘 원시 팔레트다.
   - `--grey-50` ~ `--grey-950`
   - `--blue-50` ~ `--blue-950` (브랜드. `#0368F1`을 기준점으로 명도 단계를 만든다. 기존 `--brand-*` 초록 11단계는 제거한다)
   - `--red-*` (파괴적 동작용. 지금 `--destructive` 한 값만 있다)
   - 투명도 변형 `--alpha-grey-*`. 배경 위에 겹쳐도 색이 뜨지 않아 구분선·오버레이에 쓴다.
2. **Semantic 레이어**를 만든다. 화면에서 부르는 이름은 전부 여기까지만 온다.
   - `--fill-base`, `--fill-surface`, `--fill-elevated`, `--fill-brand`, `--fill-brand-weak`
   - `--text-primary`, `--text-secondary`, `--text-disabled`, `--text-brand`, `--text-danger`
   - `--border-default`, `--border-strong`, `--border-brand`
3. **브리지**를 둔다. shadcn 컴포넌트가 참조하는 이름(`--background`, `--card`, `--primary`, `--muted`, `--border`, `--ring` 등)을 지우지 않고 시맨틱 토큰을 가리키게 한다.
   ```css
   --background: var(--fill-base);
   --card: var(--fill-surface);
   --border: var(--border-default);
   ```
   이렇게 하면 `shared/ui`의 컴포넌트를 한 줄도 고치지 않고 새 체계로 갈아탈 수 있다. 컴포넌트 마이그레이션은 4단계에서 필요한 것만 한다.
4. 지도 색은 `--map-level-*`를 유지하되 Base의 blue 단계를 참조하도록 바꾼다. 라이트에서 흰색 → 진한 파랑으로 간다.
5. 초록을 참조하던 값을 함께 옮긴다. `--primary`, `--secondary`, `--accent`, `--ring`, 그리고 그림자에 쓰인 `color-mix(... var(--brand-950) ...)`가 대상이다.
6. Component 레이어는 만들지 않는다. 지금 규모에서 `button-fill-primary` 같은 3단계 토큰은 이름만 늘린다. 필요해지면 그때 추가한다.

검증:

- 브랜드 색을 제외한 나머지(배경·카드·경계·텍스트)는 마이그레이션 전후 겉모습이 같다.
- 초록이 쓰이던 자리가 빠짐없이 파랑으로 바뀌었다. `grep -ri "brand-\|428c58" src app`이 비어 있다.
- `grep -r "#[0-9a-fA-F]\{6\}" src --include=*.tsx`가 비어 있다.

## 2단계: 다크 팔레트 값 산출

1. 라이트와 1:1로 대응하는 다크 값을 만든다. 토큰 이름은 그대로 두고 값만 바꾼다.
2. 다크는 명도 곡선을 따로 잡는다. 라이트 값을 그대로 반전하면 어두운 배경에서 색이 튄다.
3. 배경은 순수 검정을 쓰지 않는다. `--fill-base`는 `grey-950` 근처, `--fill-surface`는 한 단계 밝게 두어 카드가 배경 위에 뜬 것처럼 보이게 한다.
4. 브랜드 파랑은 다크에서 채도를 낮추고 명도를 올린다. 어두운 배경 위의 진한 파랑은 대비가 모자라고, 채도가 높으면 눈이 부시게 튄다.
5. 지도 5단계는 별도로 설계한다. 라이트는 흰색에서 진한 파랑으로, 다크는 어두운 회색에서 밝은 파랑으로 방향이 반대다. 단계 간 명도 차를 최소 8% 이상 둔다.
6. 그림자는 다크에서 거의 보이지 않는다. `--fill-elevated`의 명도 차로 위계를 대신한다.

검증:

- 본문 텍스트 대비 4.5:1, 보조 텍스트·아이콘 3:1 이상.
- 지도 5단계를 나란히 놓고 인접 단계가 구분된다.
- 브랜드 파랑이 다크 배경에서 3:1 이상이다.

## 3단계: 모드 전환 구현

1. 저장은 **쿠키**를 쓴다. 값은 `light` · `dark` · `system` 셋이다.
   - 서버 컴포넌트에서 쿠키를 읽어 `<html class="dark">`를 직접 렌더하므로 깜빡임이 없다.
   - localStorage 방식(next-themes)은 의존성이 늘고 `<head>`에 블로킹 스크립트가 필요하다.
2. `system`일 때는 클래스를 붙이지 않고 CSS가 판단하게 한다. 다크 값을 두 곳에 정의한다.
   ```css
   .dark { /* 다크 토큰 */ }
   @media (prefers-color-scheme: dark) {
     :root:not(.light) { /* 같은 다크 토큰 */ }
   }
   ```
   `@custom-variant dark`도 두 조건을 모두 만족하도록 다시 쓴다. Tailwind 4의 다중 조건 문법을 쓰며, 실제 생성 CSS를 확인한다.
3. 설정 화면에 3지 선택을 둔다. 서버 액션으로 쿠키를 쓰고 `revalidatePath`로 갱신한다. 새 클라이언트 상태를 만들지 않는다.
4. `theme-color` 메타를 모드별로 둘 준다. Next의 viewport export는 `media`를 지원한다.
   ```ts
   themeColor: [
     { media: "(prefers-color-scheme: light)", color: "#FAFAF8" },
     { media: "(prefers-color-scheme: dark)", color: "#101211" },
   ]
   ```
5. PWA 상태 표시줄은 `appleWebApp.statusBarStyle`이 정적이라 모드에 따라 바꿀 수 없다. `default`로 두고 실기기에서 다크일 때 어떻게 보이는지 확인한 뒤 결정한다.

검증:

- 세 모드를 오가며 새로고침해도 선택이 유지된다.
- `system`에서 기기 설정을 바꾸면 새로고침 없이 즉시 반영된다.
- 다크로 저장한 뒤 첫 진입 시 흰 화면이 스치지 않는다.
- 설치한 PWA에서도 동일하게 동작한다.

## 4단계: 컴포넌트와 화면 정리

1. `shared/ui`의 `dark:` 유틸을 점검한다. 시맨틱 토큰으로 해결되는 것은 지우고, 다크에서만 필요한 처리(입력 필드 배경 등)만 남긴다.
2. 화면에 남은 하드코딩 색을 찾아 토큰으로 바꾼다. `color-mix(... var(--brand-950) ...)` 형태의 그림자도 포함한다.
3. 다크에서 어색해지는 요소를 개별 점검한다.
   - 하단 내비게이션의 불투명 배경과 헤어라인
   - 카드 위 카드(다이얼로그) 위계
   - 기록 타임라인의 세로선과 점
   - 선택 칩의 `bg-primary/10` 채움
   - 하단 내비게이션 활성 탭의 듀오톤 채움(`fill-opacity 0.22`)
   - 로그인 화면의 격자 패턴과 블러 원
4. 지도 SVG의 `fill-map-*` 클래스가 새 값을 받는지 확인한다.

검증:

- 7개 화면 + 다이얼로그 4종을 라이트·다크로 각각 확인한다.
- 다크에서 경계가 사라져 요소가 붙어 보이는 곳이 없다.

## 5단계: 문서화

1. `docs/design-token.md`를 새 체계로 갱신한다. Base·Semantic 두 표와 라이트·다크 값을 함께 싣는다.
2. `docs/convention.md`에 "색은 시맨틱 토큰으로만 참조한다" 규칙을 추가한다.
